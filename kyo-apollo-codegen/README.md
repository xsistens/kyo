# kyo-apollo-codegen

Generates the Scala code that [kyo-apollo](../kyo-apollo/README.md) operations are
written against, from a GraphQL schema in SDL: one selector object per type, the three
operation roots, enums, input objects and custom scalars. It reads the schema only.
Operations are written inline in Scala against the generated selectors, so a project
keeps no `.graphql` operation files and gets no class per operation; the result type
of each operation is inferred from the fields it selects.

The generator does not depend on kyo-apollo. Its output is compiled against kyo-apollo
by the `kyo-apollo-codegen-it` project on every build, and every example in this README
is compiled against the sources generated there from the bundled example schema
(`src/main/resources/codegenExample/schema.graphql`).

## Getting Started

In kyo's own build, a project generates its sources with `apolloCodegenSettings` and
two required keys:

```scala doctest:expect=skipped
lazy val `countries-client` =
    project
        .dependsOn(`kyo-apollo`.jvm)
        .settings(
            apolloCodegenSettings,
            apolloSchema         := baseDirectory.value / "schema.graphql",
            apolloPackage        := "countries.graphql",
            apolloScalarMappings := Map("DateTime" -> "java.time.Instant"),
            apolloClientFields   := Seq("Country.isFavorite: Boolean = false")
        )
```

`apolloGenerate` runs before every compile and writes into
`Compile / sourceManaged / kyo-apollo-codegen`. It rewrites only files whose content
changed, so an unchanged schema triggers no recompilation, and it deletes the
generated sources of types that left the schema. Files without the generator's
`// GENERATED by apollo-codegen` marker are never touched.

The task is defined in kyo's `build.sbt`; there is no sbt plugin. Another build runs
the same generator, `kyo.apollo.codegen.CodegenRunner`, with these options:

| Option | Meaning |
|--------|---------|
| `--schema <file>` | the schema SDL (required) |
| `--out <dir>` | the directory the sources are written to (required) |
| `--package <name>` | the package the sources declare (required) |
| `--scalar <Name=fully.qualified.Type>` | map a custom scalar to a Scala type with a `Schema` (repeatable) |
| `--client-field "<Type.field: ScalaType = default>"` | declare a local `@client` field (repeatable) |

A failure stops generation with a `CodegenException` whose message names the
schema coordinate, option or entry at fault: `UnknownType("Mystery", "Query.mystery")`
for a field whose type the schema does not declare, `MissingOption("--schema")`,
`MalformedClientField(entry)`, `ParseFailure(file, message)`. Run in a forked JVM, that
is one line on stderr and a non-zero exit.

## What it generates

| Schema | Generated Scala |
|--------|-----------------|
| `type Country { ... }` | `sealed trait Country` and `object Country` with one selector per field, plus the same selectors chained on a selection (`_.code.name`) |
| `type Query`, `Mutation`, `Subscription` | `object Queries`, `Mutations`, `Subscriptions`, one method per root field, with the field's arguments |
| `interface Node`, `union SearchResult` | a selector object whose `on<Type>` branches select the fields of each implementing or member type |
| `enum Color { RED GREEN BLUE }` | `enum Color` with an extra `Unknown__(raw)` case, `values: Chunk[Color]` and `valueOf(name): Maybe[Color]` |
| `input UpdateCountryInput { ... }` | `final case class UpdateCountryInput(...) derives Schema` |
| a mapped `scalar DateTime` | a `given Schema` for the mapped Scala type in `CustomScalars` |
| every `--client-field` | a descriptor in `ClientFields` and a chained accessor next to the server fields |
| all object types | `SchemaIdentities.generator`, a cache key generator over the `CacheIdentity` givens in scope |

A nullable field decodes to `Maybe`, a list field to `Chunk`, and an optional argument
defaults to `Absent`.

## Writing operations

A root field takes the fields to select, either as a function that chains them onto
the empty selection or as a selection value combined with `~`. `toQuery()`,
`toMutation()` and `toSubscription()` turn a root selection into an operation:

```scala
import kyo.apollo.api.*

val germany = Queries.country("DE")(_.code.name.capital).toQuery()

val nameAndCapital = Country.name ~ Country.capital
val europe =
    Queries.countries(filter = Present(CountryFilter(continent = Present(Continent.EUROPE), search = Absent)))(nameAndCapital)
        .toQuery()
```

<!-- doctest:scope=inherited
```scala
val germanyIsTyped: Query.Normalizable[(country: Maybe[(code: String, name: String, capital: Maybe[String])])] =
    germany
val europeIsTyped: Query.Normalizable[(countries: Chunk[(name: String, capital: Maybe[String])])] =
    europe
```

`germany` has the result type
`(country: Maybe[(code: String, name: String, capital: Maybe[String])])`, and `europe`
has `(countries: Chunk[(name: String, capital: Maybe[String])])`.

A field of an object type takes its own selection, so nesting follows the schema:

```scala
val firstPage = Queries.countriesConnection(first = Present(10))(
    _.edges(_.cursor.node(_.code.name)).pageInfo(_.endCursor.hasNextPage)
).toQuery()
```

A field whose type is an interface or a union selects through `on<Type>` branches.
Each branch decodes to `Maybe`, and exactly one is `Present` for a given object; the
interface's own fields sit next to the branches:

```scala
val hits = Queries.search("ber")(_.onCountry(_.code.name).onReport(_.title)).toQuery()

val someNode = Queries.node("u1")(_.onUser(_.name.favoriteColor).onReport(_.title).id).toQuery()
```

Mutations take generated input objects, and subscriptions stream the selected fields
of every event. A mapped custom scalar decodes to its Scala type, here
`updatedAt: Maybe[java.time.Instant]`:

```scala
val moveCapital = Mutations.updateCountry(
    UpdateCountryInput(code = "DE", capital = Present("Berlin"), emoji = Absent)
)(_.code.capital).toMutation()

val europeanUpdates =
    Subscriptions.countryUpdated(continent = Present(Continent.EUROPE))(_.code.capital.updatedAt).toSubscription()
```

## Enums a server can extend

A server may add an enum value after the client was generated. Every generated enum
therefore has an `Unknown__(raw)` case: a name the client does not know decodes to it
instead of failing the response, and encodes back to the same name. A `match` over an
enum names that case too:

```scala
def describe(color: Color): String =
    color match
        case Color.RED            => "red"
        case Color.GREEN          => "green"
        case Color.BLUE           => "blue"
        case Color.Unknown__(raw) => s"a color this client does not know: $raw"

val declared: Chunk[Color] = Color.values
val parsed: Maybe[Color]   = Color.valueOf("GREEN")
```

`values` lists only the declared cases, and `valueOf` returns `Absent` for a name it
does not know rather than an `Unknown__`.

## Local fields and cache identities

A `@client` field lives only in the normalized cache: it is left out of the document
the server receives, and a read that finds no value returns the declared default.
`--client-field "Country.isFavorite: Boolean = false"` generates an accessor that
chains like a server field:

```scala
val withFavorite = Queries.country("DE")(_.code.name.isFavorite).toQuery()
```

A normalized cache keys records by identity. Declare the identity of a type as a
`given`, and `SchemaIdentities.generator` picks up every such given in scope; types
without one are keyed by `id`:

```scala
import kyo.apollo.ApolloClient
import kyo.apollo.cache.normalized.*
import kyo.apollo.cache.normalized.api.CacheIdentity

given CacheIdentity[Country] = CacheIdentity.by(_.code)

val cachedConfig =
    ApolloClient.Config("https://countries.example/graphql").normalizedCache(MemoryCache(), SchemaIdentities.generator)
```
